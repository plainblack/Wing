                W I N G   C H A N G E S
----------------------------------------------------------
This file tracks the changes to Wing over time. Especially
with respect to new features and compatibility changes.
==========================================================

2026-11-07
 * UPGRADE: Wing::Session check_permissions no longer passes every permission for admins (restored by #111). An admin's app (SSO) token now needs the same API key grants as anyone else's on routes that ask for permissions, such as edit_my_account for the /account pages and PUT or DELETE /api/user/:id, and is refused with 450 without them. Site sessions are unchanged (#113).
 * .agent-policy.json gains an approval section, so agent-policy merge asks a human before landing changes to Wing's session, SSO, API key, user and privilege code, the Wing::DB::Result and ResultSet permission checks, every Wing REST and web route module, the add_class templates, the init app's account and user admin views, auth mail kits and admin setup, var/init/etc/nginx.conf, var/systemd, and edits to var/init/dbicdh (#112).
 * UPGRADE: App (SSO) tokens are refused only by admin checks and by privileges that opt in. Reverts #103 and #105: is_site_admin is gone, and can_edit, verify_posted_params, include_admin, format_list, the user search by email, POST /api/user, md5_password and the generated is_<privilege> use is_admin again, so an admin's app token gets the admin bypass. Wing::Session check_permissions passes every permission for admins again (removed in #92); ended sessions and missing users still get 401 and deactivated users 450. verify_is_admin now refuses an app session with 450 and asks for a site session. A privilege field defined with refuse_app_tokens => 1 makes its verify_is_<privilege> refuse an app session with 450, even for holders and admins; is_<privilege> never refuses. Setting a password through verify_posted_params still requires can_edit (#111).
 * UPGRADE: Revert the #86 Wing::ContentFilter format_html heading change, which nobody asked for. Seven or more # marks render as an h6 again (#######x becomes <h6>#x</h6>), quotes, rules and headings swallow the blank lines next to them again, an empty heading takes the next line as its text again, and a headings option with levels outside 1 to 6 no longer dies (#110).
 * author.t/rest_mutation_auth.t creates users through generic CRUD with the admin's site session, since #103 stopped an admin's SSO session from bypassing the model's edit check (#109).
 * Add AGENTS.md, which records that Beanstalk::Client is unmaintained so agents fix its gaps in Wing instead of filing upstream issues, and reword the Wingman reserve_job comment to say why Wing sends reserve-job itself. author.t/wingman.t now tests reserve_job directly (#102).
 * wing_init_app.pl copies the mail kits unchanged instead of rendering them, so new apps keep their [% %] runtime tags (such as the To and Subject headers) and get stuck_wingman_job.mkit. Adds --root (default /data) to create the app somewhere else, and stops on an unknown option (#107).
 * The TestWing and Acquisitions test schemas use Wing::DB::ResultSet as their default resultset class, like generated applications, so author tests no longer set it on each source by hand (#106).
 * find_tenant_site matches tenants/domain literally, so its dots no longer match any character and a host such as foo.exampleXcom no longer resolves to tenant foo when tenants/domain is example.com (#108).
 * REST modules that set up relationship routes at load, such as Wing::Rest::User, Wing::Rest::Idea and Wing::Rest::Trends, load again when tenants/domain is set. generate_all_relationships no longer calls site_db, which needs a request; it registers routes for the relationships of the main schema and, when tenants/domain is set, the tenant schema. A relationship route returns 404 when the object on that host has no such relationship (#104).
 * Remove TGC-specific references: mail kit manifests no longer set a TT INCLUDE_PATH of /data/TGC/views (no kit includes other templates), the Jobber tube error no longer names TGC commands, and the author-test runner no longer clears TGC_JOBBER_ variables. author.t/no_tgc_references.t keeps TGC out of Wing (#101).
 * UPGRADE: The is_<field> and verify_is_<field> methods that wing_privilege_fields generates (including is_developer) now use is_site_admin instead of is_admin, so an admin's SSO session no longer passes them, wing_controlled_by_privilege, wing_viewed_by_privilege or check_privilege fields unless the user has that privilege itself (#105).
 * UPGRADE: Generic REST admin bypasses ignore an admin's SSO session: can_edit, verify_posted_params, include_admin, the user search by email, POST /api/user and md5_password now use the new User is_site_admin, which is false for SSO sessions. is_admin is unchanged. Setting a password through verify_posted_params now requires can_edit on an existing user, so a user can no longer set another user's password with PUT /api/user/:id (#103).
 * UPGRADE: Wing's admin web services (/api/wingman, /api/trends and /api/trendsreport, PUT /api/idea/:id/lock and unlock, DELETE /api/idea/:id) refuse SSO sessions with 450, because no API key permission grants admin rights; use a site session. Adds get_admin_by_session_id to Wing::Rest, which REST routes can use the same way as the Wing::Web keyword. verify_is_admin itself is unchanged (#100).
 * wing rest --restart and wing web --restart start the service when its PID file is missing instead of doing nothing, and wing rest and wing web now exit non-zero with what to do when start_server fails (#98).
 * UPGRADE: Wing::Session no longer checks application logins itself. An application registers a check with Wing::Session->add_validator(\&check); each check receives the session when it loads from the cache and when is_valid runs, and a false return ends the session. Sessions validate as before when no check is registered. Applications that relied on Wing's built-in login revocation must register their own check in every process before upgrading, or revoked logins stay signed in. Sessions still store auth_source, floor_login_id and absolute_expires_at (#95).
 * UPGRADE: Web account pages check permissions per route instead of refusing every SSO session: viewing settings, API keys and SSO success needs view_my_account; changing settings or API keys, deactivating and secondary verification need edit_my_account. SSO consent, Facebook linking and get_admin_by_session_id still refuse SSO sessions. Wing::Session check_permissions no longer passes every permission for admins, so an admin's SSO session needs the same grants as anyone else's on routes that ask for permissions. POST /account no longer starts a site session for an SSO session, and POST /sso/authorize refuses another user's authorization request. Removes the site_session option of get_session; applications that passed it must check $session->sso themselves (#92).
 * UPGRADE: Wing no longer refuses requests whose Origin or Sec-Fetch-Site does not match the site, so front ends on another host can call REST with an explicit session_id again. Removes Wing::RequestSecurity::same_origin_error and the rest/allow_cookieless_cross_origin_writes setting; delete that setting from wing.conf. Session cookies keep SameSite=Lax. Applications that want an origin check own it (#91).
 * Sessions cache their user per user in user-data-<id> instead of in each session, so users with no recent change are read from the cache again. User update and delete remove that entry and set user-changed-<id> to 1 for five minutes, during which sessions read the user from the database; other applications that change users must remove user-data-<id>, or set any truthy user-changed-<id> for at least seven days and not remove it. Filling the cache reads the user with a shared lock, so it waits for an open transaction that changed the user. Restores User user_to_json and user_from_json (#93).
 * UPGRADE: users changed while #82 was deployed keep its never-expiring user-changed-<id> marker and are read from the database on every request until their next change or login replaces it with the five-minute marker. Removing those keys is safe (#93).
 * UPGRADE: client_ip now returns X-Real-IP as one value instead of its last comma-separated entry. The generated nginx.conf sends X-Real-IP $remote_addr resolved by the realip module (real_ip_header X-Forwarded-For, real_ip_recursive on). Existing installations must replace X-Real-IP $proxy_add_x_forwarded_for with the same directives, add set_real_ip_from for each load balancer range, and build nginx with --with-http_realip_module; otherwise sessions record a comma list (#94).
 * The generated wing.conf keeps wingman/email_tube "wingman.email", so autokick can still kick the default tube, and no longer lists it in autokick_excluded_tubes, because autokick never kicks the email tube. Explicit --watch / --watch-only lists must include wingman.email. Existing configurations are unchanged (#94).
 * wing autokick_jobs kicks fresh buried jobs again in tubes not in wingman/autokick_excluded_tubes. A stuck, old or unreadable buried head stays buried, alerts wing_admin and is moved behind the other buried jobs so fresh jobs behind it are still kicked (needs beanstalkd 1.12+). The email tube (wingman/email_tube, or the default tube when unset) is never kicked, and buried SendTemplatedEmail, EmailAllAdmins and EmailAllUsers jobs in any tube are never kicked or moved. Adds Wingman->reserve_job and Wingman->email_phases (#89, #60, #99).
 * Queued email that fails to send, fan out or delete stays buried and emails wing_admin the stuck_wingman_job alert with the job ID at once; SendTemplatedEmail logs a bad address as a warning and deletes the job. Wing->send_templated_email now raises Ouch 442 instead of 504 when the SMTP server permanently refuses the recipients (#90).
 * Send queued email (SendTemplatedEmail, EmailAllAdmins) whether or not its tube is in wingman/autokick_excluded_tubes, so installations without that setting deliver queued email again (#88).
 * Run author tests with the Perl runner author.t/run.pl against the dev MySQL and Beanstalkd in author.t/etc/test.conf; nothing starts its own mysqld, beanstalkd, nginx or browser, and the Node and Playwright checks are gone (#96).
 * Remove the Python test runner bin/agent-tests.py and the Python author tests; author.t/run.pl and Perl tests replace them (#96).
 * List the author-test Perl modules in bin/setup/03_install_perl_modules.sh (#96).
 * Fix the Wingman admin tube job list, which missed jobs once broker job IDs passed about 100, ignored buried and delayed jobs, and peeked the default tube instead of the requested one (#96).

2026-11-04
 * UPGRADE: Session cookies set by login, POST /api/session and admin become now carry SameSite=Lax, and Secure when Dancer's request->secure is true. Behind a proxy that ends TLS, enable Dancer's behind_proxy only if the proxy overwrites X-Forwarded-Proto and X-Forwarded-Host and the app cannot be reached directly. The generated nginx.conf now sets both headers (#54).
 * UPGRADE: generate_create, generate_update and generate_delete given a permissions option, even an empty array or undef, now require a logged-in user and return its 441, 401 or 450 error before model verification, lookup or mutation, instead of continuing with no user. Omitting permissions keeps the optional user lookup (#70).
 * generate_read, generate_relationship and generate_options return public fields when authentication or the permission check fails, and pass rate-limit and other errors through. describe and format_list treat an explicit current_user => undef as anonymous and look up the user only when current_user is omitted. generate_crud passes its options to all five generators, generate_options honors db_class_name, and extra_processing runs only when defined (#72, #73).
 * UPGRADE: Built-in REST routes: the User relationships (apikeys, apikeypermissions) and GET /api/apikey/:id need view_my_account, and SSO sessions without it see public fields only; GET /api/user, /api/user/whoami and /api/user-not-me describe users publicly for such sessions. GET /api/user/:id/firebase-jwt and the web GET /chat page need edit_my_account. The query search on GET /api/user and /api/user-not-me matches email only for admins (#75, #80, #81, #83).
 * UPGRADE: Wing::Rest get_session returns 401 for an ended, expired or password-changed session before checking permissions, and get_user_by_session_id returns 401 instead of undef when the session's user is gone. A Wing::Session object passed to get_session is reloaded by its id and checked like a session id, instead of being returned unchanged. Wing::Session end clears the session's user for the rest of the request, a session whose user no longer exists is ended, and check_permissions refuses permanently deactivated admins with 450. Adds Wing::Session is_valid. Wing::Web get_session and get_user_by_session_id accept permissions like Wing::Rest's (#74, #76, #77, #78, #79, #83).
 * UPGRADE: Wing's admin web pages, including Trends and Wingman, use get_admin_by_session_id, which refuses SSO sessions with 450 (#85).
 * UPGRADE: Account pages pass the account description to their templates: account/index.tt reads its properties from account.json and account/apikeys.tt lists keys from apikeys_uri. Applications with copied account templates must make the same change (#85).
 * UPGRADE: Adds the client_ip Dancer keyword to Wing::Rest and Wing::Web. Wing uses it for the IP address of sessions, SSO requests, descriptions and expanded_params, including admin become sessions, which recorded the direct peer before. Admin become ends the admin's session only after the new one starts. Applications with their own client_ip sub in a package that uses Wing::Rest or Wing::Web must rename it (#53, #66).
 * UPGRADE: UserTenantSSO's master_user_id is nullable for tenant-local accounts and unique when set, and posted account fields can no longer set it. Existing applications must generate and apply their own migration allowing NULL before creating tenant-local accounts (#65).
 * Adds the optional wingman/email_tube setting. When it is set, SendTemplatedEmail and EmailAllAdmins jobs with no explicit tube go to it, including Wing->send_templated_email and admin fan-out, and an invalid name stops email publication. Default wingman.pl workers watch the default tube and the email tube; --watch-only replaces both. wing do --tube defaults to the phase's tube, and the admin tube page's Add Job sends email phases without a tube. Unset or null keeps default-tube routing. Wingman::Role::EmailRecovery has the adoption steps. Adds Wingman->email_tube and Wingman->email_tube_for_phase (#69, #71).
 * wingman.pl signals only its own live workers on stop and HUP (#51).
 * Wing::ContentFilter headings match only their exact number of # marks, and quotes, rules and headings no longer swallow the blank lines before them. A headings option with values other than 1 to 6 now dies (#86).
